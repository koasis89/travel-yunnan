## 2. 사전 결정 사항 (W0)

### W0-1. 공개 범위 결정

- 목적: 예약번호·예약자 영문명·숙소 전화가 외부에 노출되지 않게 한다.
- 작업 내용: 아래 둘 중 하나를 고른다. 기본 권장은 A안이다.
  - A안(권장): Cloudflare Access 로 가족 3명 이메일만 접근. 데이터는 앱과 동일하게 둔다.
  - B안: 공개 사이트. 내보내기 단계에서 예약번호·예약자명을 빼고(`--public`), 주소·전화만 남긴다.
- 완료 기준: 선택 결과와 가족 3명의 이메일 주소를 이 문서 끝 "결정 기록"에 적는다.

### W0-2. 중국 내 접속 방식 확인

- 목적: 현지에서 사이트가 열리는지 미리 판단한다.
- 작업 내용:
  - 중국 본토에서는 해외 사이트가 회선에 따라 막히거나 느릴 수 있다. 한국 통신사 로밍이나 로밍형 eSIM 은 한국을 거쳐 나가므로 대체로 열리지만, 중국 현지 유심은 막힐 수 있다.
  - 그래서 오프라인 캐시(W4)를 필수로 하고, 출국 전 한국에서 각자 사이트를 한 번 열어 캐시를 채운다.
- 완료 기준: 3인의 현지 통신 방식(로밍·eSIM·현지 유심)을 확인한다.

### W0-3. 계정 준비

- 작업 내용:
  1. Cloudflare 계정 생성(무료).
  2. Cloudflare 와 GitHub 연결 권한 부여: `koasis89/travel-yunnan` 리포지토리만 선택.
  3. 개발 PC 에 Node.js 20 LTS 이상 설치, `node -v` 확인.
- 완료 기준: Cloudflare 대시보드 로그인, `node -v` 가 20 이상.

### 무료 호스팅 비교 (참고)

## 3. 데이터 내보내기 (W1)

### W1-1. 웹용 내보내기 스크립트 `tools/export_web.py`

- 목적: 앱 데이터 중 웹에 필요한 것만 골라 `web/src/data/` 에 복사한다. 데이터 원본은 여전히 엑셀 하나다.
- 작업 내용:

| 포함 | 제외 |
|---|---|
| days, schedule, lodgings, lodging_todos, meals, foods, transport, budget, rates, weather, packing, notes, places, place_links, template_links, notifications, emergency(연락처·고산병만) | words, foodNames, maps, map_hotspots |
| phrases 중 택시 카드 보조 문장만(`px-001`~`px-004`, 위챗 장문 `msg-*`) | phrases 나머지 |

  - `--public` 옵션이면 lodgings 의 `bookingNo`, `bookedBy` 를 비운다.
  - 음식 사진은 `assets/foods/` → `web/public/images/foods/` 로 복사한다.

### W4-3. 택시 카드 상세

- 전체 화면: 버튼으로 `document.documentElement.requestFullscreen()` 호출(아이폰 사파리는 미지원 → 일반 화면 유지).
- 화면 켜짐: `navigator.wakeLock.request('screen')` 을 카드가 열려 있는 동안 유지하고 닫을 때 해제한다. 지원하지 않는 브라우저는 무시한다.
- 밝기: 웹에서는 바꿀 수 없으므로 상단에 "화면 밝기를 최대로 올려 기사님께 보여주세요" 안내를 둔다.
- 가로 모드: CSS `@media (orientation: landscape)` 에서 상호·주소만 크게 남긴다.
- 화면을 누르면 버튼 영역을 숨긴다(앱과 동일).

### W4-6. 일정 알림 대체: 캘린더 파일

- `notifications.json` 12건을 iCalendar(.ics) 파일로 만들어 내려받게 한다. 각 항목에 `TZID=Asia/Shanghai`, 알림(VALARM) 0분 전을 넣는다.
- 휴대폰 기본 캘린더(구글·애플)로 열면 일정과 알림이 함께 등록된다. 웹 푸시 알림보다 훨씬 단순하고 오프라인에서도 울린다.
- 완료 기준: 안드로이드 구글 캘린더, 아이폰 캘린더에서 각각 12건이 현지 시각으로 들어간다.

## 7. 오프라인·홈 화면 추가 (PWA, W5)

### W5-1. vite-plugin-pwa 설정

```ts
// vite.config.ts
import { VitePWA } from 'vite-plugin-pwa';
export default defineConfig({
  plugins: [react(), VitePWA({
    registerType: 'autoUpdate',
    includeAssets: ['icons/*.png', 'images/foods/*'],
    manifest: {
      name: '윈난 7박 8일 · 딸들과 함께 여행을', short_name: '윈난 여행',
      theme_color: '#1F6F6B', background_color: '#F6F3EC', display: 'standalone', lang: 'ko',
      icons: [{ src: 'icons/icon-192.png', sizes: '192x192', type: 'image/png' },
              { src: 'icons/icon-512.png', sizes: '512x512', type: 'image/png', purpose: 'any maskable' }],
    },
    workbox: { globPatterns: ['**/*.{js,css,html,json,png,jpg,jpeg,svg,woff2}'] },
  })],
});
```

- 데이터 JSON 과 음식 사진까지 모두 미리 캐시한다(전체 약 2MB).
- 완료 기준: 한 번 연 뒤 비행기 모드에서 모든 화면이 열린다.

### W5-2. 홈 화면에 추가 안내

- 안드로이드 크롬: 메뉴 → "홈 화면에 추가"(또는 설치 배너).
- 아이폰 사파리: 공유 → "홈 화면에 추가".
- 더보기 화면에 위 안내와 "마지막 데이터 갱신: 버전 2026-12-10" 표시를 둔다.

### W5-3. 업데이트 확인

- 새 버전이 배포되면 다음 실행 때 자동 갱신된다(`autoUpdate`). 화면 하단 데이터 버전으로 확인한다.

## 8. 배포 (W6)

### W6-1. Cloudflare Pages 프로젝트 생성

1. Cloudflare 대시보드 → Workers & Pages → Create → Pages → Connect to Git → `koasis89/travel-yunnan` 선택.
2. 빌드 설정:

| 항목 | 값 |
|---|---|
| Production branch | `main` |
| Framework preset | Vite |
| Root directory | `web` |
| Build command | `npm run build` |
| Build output directory | `dist` |
| 환경 변수 | `NODE_VERSION=20` |

3. 프로젝트 이름을 정한다. 주소는 `https://<프로젝트명>.pages.dev` 가 된다(예: `yunnan-ko.pages.dev`).

- 완료 기준: 첫 배포 성공, 주소로 접속된다.

### W6-2. 접근 제한 (A안)

1. Cloudflare 대시보드 → Zero Trust → 팀 이름 정하기 → 무료 플랜 선택. 가입 과정에서 결제수단 등록을 요구할 수 있으나 무료 플랜은 청구되지 않는다.
2. Settings → Authentication → Login methods 에 "One-time PIN" 이 켜져 있는지 확인한다.
3. Access → Applications → Add an application → Self-hosted:
   - Application domain: `<프로젝트명>.pages.dev`
   - 미리보기 배포도 막으려면 `*.<프로젝트명>.pages.dev` 를 하나 더 추가한다.
   - Session duration: 1 month(여행 중 재로그인 줄이기)
4. Policy: Action = Allow, Include = Emails → 가족 3명 이메일.
5. 시크릿 창에서 접속 → 이메일 입력 → 받은 6자리 코드로 로그인되는지 확인한다.

- 주의: 오프라인 캐시는 로그인 후 받은 파일로 동작한다. 세션이 만료돼도 캐시된 화면은 열리지만, 데이터 갱신을 받으려면 다시 로그인해야 한다. 출국 직전(12/15) 각자 한 번 로그인해 둔다.
- 완료 기준: 등록되지 않은 이메일은 코드가 오지 않고 접근이 거부된다.

### W6-3. 보안 헤더 `web/public/_headers`

```
/*
  X-Robots-Tag: noindex, nofollow
  X-Content-Type-Options: nosniff
  Referrer-Policy: no-referrer
  Permissions-Policy: geolocation=(), camera=(), microphone=()
```

- 검색엔진 수집을 막는다(B안 공개일 때 특히 필요).

### W6-4. 자동 배포와 CI

- `main` 에 푸시하면 Cloudflare 가 자동으로 다시 빌드·배포한다.
- 기존 GitHub Actions(`.github/workflows/android.yml`)에 웹 작업을 추가한다: `export_web.py` 실행 후 `git diff --exit-code web/src/data`(내보내기 누락 방지), `npm ci`, `npx vitest run`, `npm run build`.

## 11. 운영 시 주의

- 데이터는 엑셀 한 곳에서만 고친다. 웹 JSON 을 직접 고치지 않는다(다음 내보내기에서 덮어쓴다).
- 완료 표시·체크·경비는 기기별 저장이라 가족 간에 공유되지 않는다. 공유가 필요해지면 Cloudflare D1(무료 SQLite)·Workers 로 확장할 수 있으나, 이 절차서 범위 밖이다.
- 여권 정보는 웹에 넣지 않는다. 앱의 긴급·여권 화면이나 종이 사본을 쓴다.
- 무료 플랜 조건은 바뀔 수 있다. 12/1 데이터 동결 때 Cloudflare 대시보드에서 프로젝트·Access 정책이 그대로인지 확인한다.
