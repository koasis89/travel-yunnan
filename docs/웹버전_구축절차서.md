## 2. 사전 결정 사항 (W0)

### W0-1. 공개 범위 결정

- 목적: 예약번호·예약자 영문명·숙소 전화가 외부에 노출되지 않게 한다.
- 결정(2026-11-05): **C안 · 이메일 입력 로그인 + 데이터 암호화**를 쓴다. Cloudflare Access(A안)는 쓰지 않는다.
  - 화면: 처음 열면 이메일 입력란 하나만 보인다. 허용된 3개 이메일 중 하나를 넣으면 열린다. 인증 메일·코드는 없다.
  - 보호 방식: 화면에서 이메일을 비교만 하면 데이터 파일은 누구나 내려받을 수 있다. 그래서 빌드 때 데이터를 암호화하고, 허용 이메일로만 풀리는 열쇠를 함께 둔다(W6-2). 사이트에는 이메일 원문이 남지 않는다.
  - 한계: 이메일은 비밀번호가 아니다. 가족 이메일을 아는 사람은 열 수 있다. 무작위 방문자·검색엔진·주소만 아는 사람은 내용을 볼 수 없다.
- 참고(다른 안): A안은 Cloudflare Access 로 이메일 일회용 코드 인증, B안은 공개 사이트에서 예약번호·예약자명을 빼는 방식이다(`--public`).
- 완료 기준: 허용 이메일 3개를 "결정 기록"에 적는다. 빌드에는 환경 변수로만 넣는다.

### W0-2. 중국 내 접속 방식 확인

- 목적: 현지에서 사이트가 열리는지 미리 판단한다.
- 작업 내용:
  - 중국 본토에서는 해외 사이트가 회선에 따라 막히거나 느릴 수 있다. 한국 통신사 로밍이나 로밍형 eSIM 은 한국을 거쳐 나가므로 대체로 열리지만, 중국 현지 유심은 막힐 수 있다.
  - 그래서 오프라인 캐시(W4)를 필수로 하고, 출국 전 한국에서 각자 사이트를 한 번 열어 캐시를 채운다.
- 완료 기준: 3인의 현지 통신 방식(로밍·eSIM·현지 유심)을 확인한다.

### W0-3. 계정 준비

- 작업 내용:
  1. Cloudflare 계정 생성(무료). Zero Trust(Access) 가입은 필요 없다.
  2. Cloudflare 와 GitHub 연결 권한 부여: `koasis89/travel-yunnan` 리포지토리만 선택.
  3. 개발 PC 에 Node.js 20 LTS 이상 설치, `node -v` 확인.
- 완료 기준: Cloudflare 대시보드 로그인, `node -v` 가 20 이상.

### 무료 호스팅 비교 (참고)

| 서비스 | 비공개 리포 연결 | 무료 접근 제한 | 판단 |
|---|---|---|---|
| Cloudflare Pages + Access | 가능 | 이메일 일회용 코드(50명까지 무료) | 권장 |
| GitHub Pages | 무료 계정은 공개 리포만 가능 | 없음 | 비권장(리포 전체 공개 필요) |
| Netlify | 가능 | 비밀번호 보호는 유료 플랜 | B안(공개)일 때만 대안 |
| Vercel | 가능 | 무료 플랜의 보호 기능이 제한적 | B안일 때만 대안 |

요금제는 바뀔 수 있으므로 착수 시점에 각 서비스의 가격 페이지를 다시 확인한다.

## 3. 데이터 내보내기 (W1)

### W1-1. 웹용 내보내기 스크립트 `tools/export_web.py`

- 목적: 앱 데이터 중 웹에 필요한 것만 골라 `web/src/data/` 에 복사한다. 데이터 원본은 여전히 엑셀 하나다.
- 작업 내용:

| 포함 | 제외 |
|---|---|
| days, schedule, lodgings, lodging_todos, meals, foods, transport, budget, rates, weather, packing, notes, places, place_links, template_links, notifications, emergency(연락처·고산병만) | words, foodNames, maps, map_hotspots |
| phrases 중 택시 카드 보조 문장만(`px-001`~`px-004`, 위챗 장문 `msg-*`) | phrases 나머지 |

  - `--public` 옵션이면 lodgings 의 `bookingNo`, `bookedBy` 를 비운다.
  - 음식 사진은 `assets/foods/` → `web/public/images/foods/` 로 복사한다.

### W4-3. 택시 카드 상세

- 전체 화면: 버튼으로 `document.documentElement.requestFullscreen()` 호출(아이폰 사파리는 미지원 → 일반 화면 유지).
- 화면 켜짐: `navigator.wakeLock.request('screen')` 을 카드가 열려 있는 동안 유지하고 닫을 때 해제한다. 지원하지 않는 브라우저는 무시한다.
- 밝기: 웹에서는 바꿀 수 없으므로 상단에 "화면 밝기를 최대로 올려 기사님께 보여주세요" 안내를 둔다.
- 가로 모드: CSS `@media (orientation: landscape)` 에서 상호·주소만 크게 남긴다.
- 화면을 누르면 버튼 영역을 숨긴다(앱과 동일).

### W4-6. 일정 알림 대체: 캘린더 파일

- `notifications.json` 12건을 iCalendar(.ics) 파일로 만들어 내려받게 한다. 각 항목에 `TZID=Asia/Shanghai`, 알림(VALARM) 0분 전을 넣는다.
- 휴대폰 기본 캘린더(구글·애플)로 열면 일정과 알림이 함께 등록된다. 웹 푸시 알림보다 훨씬 단순하고 오프라인에서도 울린다.
- 완료 기준: 안드로이드 구글 캘린더, 아이폰 캘린더에서 각각 12건이 현지 시각으로 들어간다.

### W6-2. 이메일 입력 로그인 (C안, 빌드 시 암호화)

Cloudflare Access 는 쓰지 않는다. 사이트 자체에 로그인 화면을 두고, 데이터는 빌드 때 암호화한다.

**구조**

```
빌드(Cloudflare Pages)                               브라우저
────────────────────────────                        ─────────────────────────────────
web/src/data/*.json ─┐                               이메일 입력
                     ├─ AES-256-GCM 암호화 ──▶ data.enc   │
무작위 데이터 키(DEK) ─┘                                ▼
                                                    PBKDF2(이메일, salt) → 열쇠
ALLOWED_EMAILS(환경 변수) ─▶ 이메일별 열쇠로 DEK 포장 ──▶ keys.json ──▶ 3개 중 하나가 풀리면 로그인
```

- 데이터 JSON 은 JS 번들에 넣지 않는다. 빌드 결과에는 암호문 `data.enc` 와 포장된 키 3개 `keys.json` 만 있다.
- `keys.json` 에는 이메일 원문이 없다. 각 항목은 `{ salt, iv, wrapped }` 이다.
- 이메일은 앞뒤 공백 제거·소문자로 맞춘 뒤 쓴다(`KOASIS03@Gmail.com ` → `koasis03@gmail.com`).
- 열쇠 유도: PBKDF2-SHA256, 반복 600,000회, 이메일마다 다른 16바이트 salt. 휴대폰에서 로그인 한 번에 1초 안팎 걸린다.
- 음식 사진·아이콘은 민감 정보가 아니므로 암호화하지 않는다.

**작업 순서**

1. 허용 이메일을 Cloudflare Pages 환경 변수로 등록한다(리포지토리에 넣지 않는다).
   - Pages 프로젝트 → Settings → Variables and Secrets → Production·Preview 모두
   - 이름 `ALLOWED_EMAILS`, 형식 Secret(암호화), 값은 쉼표로 구분: `koasis03@gmail.com,koasis99@gmail.com`
   - 로컬 개발용은 `web/.env.local` 에 같은 값을 두고 `.gitignore` 에 넣는다.
2. 암호화 스크립트 `web/scripts/encrypt-data.mjs` 를 만든다(Node 내장 Web Crypto 사용, 추가 패키지 없음).

```js
// web/scripts/encrypt-data.mjs — npm run build 의 prebuild 로 실행
import { webcrypto as c } from 'node:crypto';
import { readFileSync, readdirSync, writeFileSync, mkdirSync } from 'node:fs';
const enc = new TextEncoder();
const b64 = (u8) => Buffer.from(u8).toString('base64');
const emails = (process.env.ALLOWED_EMAILS ?? '').split(',').map((e) => e.trim().toLowerCase()).filter(Boolean);
if (emails.length === 0) throw new Error('ALLOWED_EMAILS 가 비어 있다');

const dir = 'src/data';
const bundle = Object.fromEntries(readdirSync(dir).filter((f) => f.endsWith('.json'))
  .map((f) => [f, JSON.parse(readFileSync(`${dir}/${f}`, 'utf8'))]));

const dek = await c.subtle.generateKey({ name: 'AES-GCM', length: 256 }, true, ['encrypt', 'decrypt']);
const iv = c.getRandomValues(new Uint8Array(12));
const cipher = new Uint8Array(await c.subtle.encrypt({ name: 'AES-GCM', iv }, dek, enc.encode(JSON.stringify(bundle))));
const rawDek = new Uint8Array(await c.subtle.exportKey('raw', dek));

const keys = [];
for (const email of emails) {
  const salt = c.getRandomValues(new Uint8Array(16));
  const base = await c.subtle.importKey('raw', enc.encode(email), 'PBKDF2', false, ['deriveKey']);
  const kek = await c.subtle.deriveKey({ name: 'PBKDF2', hash: 'SHA-256', salt, iterations: 600000 },
    base, { name: 'AES-GCM', length: 256 }, false, ['encrypt']);
  const kiv = c.getRandomValues(new Uint8Array(12));
  const wrapped = new Uint8Array(await c.subtle.encrypt({ name: 'AES-GCM', iv: kiv }, kek, rawDek));
  keys.push({ salt: b64(salt), iv: b64(kiv), wrapped: b64(wrapped) });
}
mkdirSync('public', { recursive: true });
writeFileSync('public/data.enc', JSON.stringify({ iv: b64(iv), data: b64(cipher) }));
writeFileSync('public/keys.json', JSON.stringify({ v: 1, iterations: 600000, keys }));
console.log(`암호화 완료: 이메일 ${emails.length}개, 데이터 ${(cipher.length / 1024).toFixed(0)}KB`);
```

3. `package.json` 에 연결한다: `"prebuild": "node scripts/encrypt-data.mjs"`. `public/data.enc`, `public/keys.json` 은 빌드 산출물이므로 `.gitignore` 에 넣는다.
4. 앱 쪽 로그인 화면 `src/pages/Login.tsx` 와 복호화 `src/store/vault.ts` 를 만든다.

```ts
// src/store/vault.ts — 로그인·자동 로그인·로그아웃
const dec = new TextDecoder();
const u8 = (s: string) => Uint8Array.from(atob(s), (ch) => ch.charCodeAt(0));
export const normalize = (e: string) => e.trim().toLowerCase();

export async function unlock(email: string): Promise<Record<string, unknown> | null> {
  const [keysFile, box] = await Promise.all([fetch('keys.json').then((r) => r.json()), fetch('data.enc').then((r) => r.json())]);
  const base = await crypto.subtle.importKey('raw', new TextEncoder().encode(normalize(email)), 'PBKDF2', false, ['deriveKey']);
  for (const k of keysFile.keys) {
    try {
      const kek = await crypto.subtle.deriveKey({ name: 'PBKDF2', hash: 'SHA-256', salt: u8(k.salt), iterations: keysFile.iterations },
        base, { name: 'AES-GCM', length: 256 }, false, ['decrypt']);
      const raw = await crypto.subtle.decrypt({ name: 'AES-GCM', iv: u8(k.iv) }, kek, u8(k.wrapped));
      const dek = await crypto.subtle.importKey('raw', raw, 'AES-GCM', false, ['decrypt']);
      const plain = await crypto.subtle.decrypt({ name: 'AES-GCM', iv: u8(box.iv) }, dek, u8(box.data));
      localStorage.setItem('login_email', normalize(email)); // 다음 실행 때 자동 로그인
      return JSON.parse(dec.decode(plain));
    } catch { /* 이 열쇠가 아니면 다음 열쇠 */ }
  }
  return null; // 허용되지 않은 이메일
}
export const savedEmail = () => localStorage.getItem('login_email');
export const logout = () => localStorage.removeItem('login_email');
```

5. 로그인 화면 동작
   - 브랜드 헤더(로고·"딸들과 함께 여행을") 아래 이메일 입력란 하나와 "들어가기" 버튼만 둔다. 키보드는 `type="email"`, `autocomplete="email"`.
   - 실패하면 "등록된 가족 이메일이 아니다"만 표시한다. 어떤 이메일이 등록됐는지는 알려 주지 않는다.
   - 성공하면 이메일을 기기에 저장해 다음부터 자동으로 연다. 더보기 화면에 "로그아웃" 버튼을 둔다.
   - 5회 연속 실패하면 30초 동안 버튼을 막는다(무작위 시도 지연).
6. 오프라인: `data.enc`, `keys.json` 도 PWA 캐시 대상에 넣는다(`workbox.globPatterns` 에 `enc` 추가). 한 번 로그인한 기기는 비행기 모드에서도 자동 로그인·복호화된다.

- 허용 이메일을 바꾸려면 환경 변수만 고치고 다시 배포한다. 기존 기기는 다음 접속 때 새 키 파일을 받아 다시 확인된다.
- 완료 기준: 세 이메일 각각 로그인 성공, 다른 이메일 거부, 개발자 도구 Network 탭에서 받은 파일에 예약번호·전화 원문이 없음.

## 11. 운영 시 주의

- 데이터는 엑셀 한 곳에서만 고친다. 웹 JSON 을 직접 고치지 않는다(다음 내보내기에서 덮어쓴다).
- 완료 표시·체크·경비는 기기별 저장이라 가족 간에 공유되지 않는다. 공유가 필요해지면 Cloudflare D1(무료 SQLite)·Workers 로 확장할 수 있으나, 이 절차서 범위 밖이다.
- 여권 정보는 웹에 넣지 않는다. 앱의 긴급·여권 화면이나 종이 사본을 쓴다.
- 무료 플랜 조건은 바뀔 수 있다. 12/1 데이터 동결 때 Cloudflare 대시보드에서 프로젝트와 `ALLOWED_EMAILS` 환경 변수가 그대로인지 확인한다.
- 이메일 로그인은 "주소를 아는 낯선 사람"을 막는 수준이다. 가족 이메일을 아는 사람은 열 수 있으므로, 더 강하게 막아야 하면 W0-1 의 A안(Cloudflare Access 일회용 코드)으로 바꾼다. 화면·데이터 구조는 그대로 두고 배포 설정만 추가하면 된다.
