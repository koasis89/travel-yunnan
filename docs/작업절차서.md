## S0. 리포지토리 정리와 환경 준비

### S0-1. 로컬 브랜치 정리

- 목적: 여권 정보가 포함된 로컬 `main` 커밋을 제거하고, 원격 main과 동일한 브랜치를 `main`으로 둔다.
- 선행조건: 원격 `koasis89/travel-yunnan` main에 `8d7a02a` 커밋이 올라가 있다.
- 작업 내용:

```bash
cd /home/user/travel-yunnan
git branch -D main
git branch -m clean-main main
git branch -u origin/main main
git status
```

- 완료 기준: `git branch -vv` 결과에 `main ... [origin/main]` 한 줄만 보인다.

### S0-2. 리포지토리 폴더 골격 생성

- 목적: 구성방안 5장의 구조를 미리 만든다.
- 작업 내용:

```bash
mkdir -p tools data/json assets/audio/phrases android
touch tools/.gitkeep data/json/.gitkeep assets/audio/phrases/.gitkeep
```

- `.gitignore`에 다음을 추가한다.

```
*.jks
keystore.properties

data/private/
```

- 완료 기준: 커밋 후 `git ls-files`에 `tools/`, `data/json/`, `assets/audio/phrases/`가 보인다.

### S0-3. 개발 환경 확인

- 목적: PC에 필요한 도구를 설치한다.
- 작업 내용:
  1. Android Studio 최신 안정판 설치. SDK Platform 34 이상, Build-Tools, Android Emulator 설치
  2. JDK 17 설치 확인: `java -version`
  3. Python 3.11 이상과 패키지 설치: `pip install openpyxl pillow edge-tts`
  4. 3인 기기의 Android 버전·개발자 옵션·USB 디버깅 활성화. 기기별 Android 버전을 기록한다.
- 완료 기준: `adb devices`에 최소 1대가 표시된다. 기기 3대의 Android 버전이 8.0 이상이다.

### S0-4. 개인정보 보관 규칙 확정

- 목적: 여권·예약번호 등 민감 정보의 위치를 정한다.
- 작업 내용:
  - 여권 정보: 리포지토리에 넣지 않는다. 앱 설치 후 기기에서 직접 입력한다(S6-1).
  - 원본 엑셀(여권 시트 포함)은 `data/private/`에 두고 `.gitignore`로 제외한다.
  - 숙소 예약번호·전화번호는 비공개 리포지토리이므로 JSON에 포함한다.
- 완료 기준: `.gitignore`에 `data/private/`가 있고, 원본 엑셀이 그 안에 있다.

## S1. 데이터 변환 파이프라인

### S1-1. 엑셀 → JSON 변환 스크립트 작성 (`tools/xlsx_to_json.py`)

- 목적: 엑셀 12개 시트를 앱이 읽는 JSON으로 바꾼다. 엑셀이 바뀌면 이 스크립트만 다시 실행한다.
- 선행조건: `data/source/yunnan_7n8d_itinerary.xlsx`
- 작업 내용: 시트별 변환 규칙을 아래와 같이 구현한다.

| 시트 | 출력 파일 | 변환 규칙 |
|---|---|---|
| 일정요약 | `days.json` | 4행부터 읽는다. `D1`~`D8`을 id로, 일자 문자열 "12/16(수)"를 `2026-12-16`로 바꾼다. 경로·주요 내용·숙박을 그대로 담는다 |
| 상세일정 | `schedule.json` | 4행부터 읽는다. 1열(일차)이 비어 있으면 직전 일차를 상속한다. 시간 "07:30~08:00"을 `timeStart`·`timeEnd`로 분리한다. 8열(팁) 뒤에 긴 중국어 메시지가 있는 행(D4 17:00, D6 10:30)은 `message` 필드로 별도 저장한다. 팁 안의 `https://surl.amap.com/...`은 `amapUrl`로 추출한다 |
| 숙소정보 | `lodgings.json` | 4~9행. 날짜 "12/17(목)~12/18(금)"을 날짜 배열로 전개한다. 전화 "A / B"를 배열로 나눈다. 쿤밍 2건은 `status: "미정"` 유지 |
| 맛집·식사 | `meals.json` | 일차가 비어 있으면 상속한다. 선택①②③을 `options` 배열로 묶고, 주소 열의 ` / ` 구분을 옵션 순서대로 대응시킨다. Amap 링크는 옵션별 `amapUrl`로 넣는다 |
| 음식설명 | `foods.json` | 지역·번호·중국어·한국어·설명·이미지 구분·출처. 이미지 파일명은 `assets/foods/{번호:02d}_{중국어}_{한국어}.*`와 대응시킨다 |
| 교통·투어비 | `transport.json`, `rates.json` | 환율 3종과 인원은 `rates.json`. 항목 행은 구분·항목·단위·단가·통화·수량·비고·총액 |
| 총비용 | `budget.json` | 4개 구분과 합계 |
| 준비물 | `packing.json`, `weather.json` | 상단 기온표는 `weather.json`(지역·일자·해발·낮·밤·특징·옷차림). 체크리스트는 분류가 비면 상속 |
| 유의사항 | `notes.json` | 구분·내용. 내용에 포함된 중국어 문장은 정규식으로 추출하여 `phrasesInline` 배열로 둔다 |

- 공통 규칙:
  - 열 머리글 위치를 코드에 고정하지 말고 머리글 행을 찾아 열 인덱스를 계산한다.
  - 출력은 UTF-8, `ensure_ascii=False`, 들여쓰기 2칸으로 저장한다.
  - 실행 후 각 파일의 건수를 표준 출력에 찍는다.
- 실행:

```bash
python3 tools/xlsx_to_json.py data/source/yunnan_7n8d_itinerary.xlsx data/json
```

- 완료 기준: 건수가 다음과 일치한다. days 8, schedule 70 내외, lodgings 6, meals 30 내외, foods 36, packing 60 내외, notes 16.

### S1-2. 회화 텍스트 → JSON 변환 스크립트 (`tools/tts_to_phrases.py`)

- 목적: `yunnan_chinese_pinyin_tts.txt`를 단어장·문장·음식명으로 분류한다.
- 작업 내용: 파일 구조는 다음과 같으므로 규칙 기반으로 나눈다.
  1. 1~104행: 중국어·병음 2줄 쌍 52개 → `words.json`
  2. 106~454행: 빈 줄로 구분된 블록. 각 블록은 같은 문장이 3회 반복되므로 첫 쌍만 취한다 → 49문장
  3. 456~540행: 음식명·식당명 쌍. 빈 줄로 나뉜 4묶음(리장 20, 샹그릴라 7, 쿤밍 7, 식당 10) → `foodNames.json`
  4. 542~596행: 주문 문장 8개(3회 반복) → 문장에 합류
  - 문장에는 순번 기준으로 범주를 부여한다. 1~9 차량예약, 10~14 차안, 15~20 숙소, 21~34 식당, 35~37 매표, 38~43 쇼핑, 44~49 역, 50~57 주문
  - `koRead`(한글 발음)와 `ko`(뜻) 열은 스크립트가 비워 두고, `data/phrases_override.csv`에서 사람이 채운 값을 병합한다
  - 같은 문장(`这是我的护照`)이 두 범주에 있으면 id를 하나로 합치고 `categories` 배열로 둔다
- 완료 기준: `phrases.json` 56건 내외, `words.json` 52건, `foodNames.json` 44건. 모든 문장에 `pinyin`이 있다.

### S1-3. 한글 발음·한국어 뜻 보강 (`data/phrases_override.csv`)

- 목적: 문장마다 한글 발음과 뜻을 채운다.
- 작업 내용: 열은 `id, zh, ko, koRead`. 엑셀 D6 행의 표기 방식("니하오, 워 시앙 위딩…")을 따른다. 56문장과 52단어를 모두 채운다.
- 완료 기준: S1-2를 다시 실행했을 때 `ko`·`koRead`가 빈 항목이 0건이다.

### S1-4. 유의사항·숙소 시트의 중국어 문장 통합

- 목적: 엑셀 안에 흩어진 문장(택시 문구, 엑스트라베드 확인, 메이투안 배달 3문장, 빵차 예약 장문 2건)을 회화 데이터에 넣는다.
- 작업 내용: `data/phrases_extra.json`을 수동 작성하고 S1-2 결과와 합친다. 장문 2건은 `category: "message"`, `copyOnly: true`로 표시한다.
- 완료 기준: 회화 범주가 구성방안 3.4절의 10개와 일치한다.

### S1-5. 검증 스크립트 (`tools/validate.py`)

- 목적: 참조 무결성을 자동 확인한다.
- 작업 내용: 다음을 검사하고 오류가 있으면 종료 코드 1을 반환한다.
  - `schedule.json`의 `dayId`가 `days.json`에 존재
  - `days.json`의 `lodgingId`가 `lodgings.json`에 존재
  - `foods.json`의 이미지 파일이 `assets/foods/`에 실재
  - `meals.json`의 `dayId`·`mapPin` 유효
  - 모든 JSON이 UTF-8로 파싱됨
- 완료 기준: 실행 결과 `OK`. 이후 커밋 전마다 실행한다.

```bash
python3 tools/validate.py && git add tools data/json && git commit -m "데이터 변환 파이프라인과 JSON 산출물 추가" && git push
```

## S2. Android 프로젝트 골격

- 목적: Compose 기반 빈 프로젝트를 만든다.

| 항목 | 값 |
|---|---|
| 프로젝트 경로 | `android/` |
| 패키지명 | `kr.koasis.travelyunnan` |

### S2-2. 의존성 추가

- 목적: 구성방안 5장의 라이브러리를 넣는다.
- 작업 내용: `libs.versions.toml`에 다음을 등록하고 `app/build.gradle.kts`에서 참조한다.
  - Compose BOM, Material 3, Navigation Compose, Lifecycle ViewModel Compose
  - Room(runtime·ktx·compiler, KSP)
  - Hilt(android·compiler, hilt-navigation-compose)
  - DataStore Preferences
  - kotlinx-serialization-json
  - Coil(이미지), WorkManager, Biometric, Security-crypto
- 완료 기준: Gradle Sync 성공, 빈 화면 실행 성공.

### S2-3. 패키지 구조 생성

```
kr.koasis.travelyunnan
├─ data
│   ├─ json       (JSON 모델: @Serializable data class)
│   ├─ db         (Room Entity, Dao, AppDatabase)
│   ├─ repo       (Repository: 조회·상태 저장)
│   └─ seed       (최초 실행 시 assets JSON → Room 적재)
├─ domain         (일차 판별, 현재 일정 계산, 문장 합성 등 순수 로직)
├─ ui
│   ├─ theme      (색·타이포: 기본 18sp, 대형 모드 24sp)
│   ├─ common     (ShowCard 전체화면, DayChips, PhoneButton, CopyButton)
│   ├─ home / schedule / taxi / phrase / map / lodging / meal / food
│   ├─ transport / expense / packing / notes / emergency / settings
│   └─ nav        (NavGraph, BottomBar)
└─ util           (Clock 주입, 밝기 제어, 외부 앱 Intent)
```

- 완료 기준: 각 패키지에 최소 1개 파일이 있고 빌드가 된다.

### S2-4. 데이터 모델·Room 스키마

- 목적: 구성방안 5장의 데이터 모델을 코드로 옮긴다.
- 작업 내용:
  - 읽기 전용 원본 테이블: `days, schedule, lodgings, meals, foods, phrases, words, transport, packing, notes, weather`
  - 사용자 상태 테이블: `checklist_state(itemId, checked)`, `schedule_done(scheduleId)`, `phrase_fav(phraseId, order)`, `phrase_recent(phraseId, at)`, `expense(id, dayId, amount, currency, category, memo, method, payer, at)`, `passport(encrypted blob, S6)`
  - `AppDatabase` 버전 1. 원본 테이블은 재적재 시 전체 교체한다(`dataVersion`을 DataStore에 기록하고 JSON의 `version`과 다르면 재적재)
- 완료 기준: 스키마 export(`room.schemaLocation`) 파일이 생성된다.

### S2-5. JSON 적재(Seeder)

- 목적: 앱 최초 실행 시 `assets/data/*.json`을 Room에 넣는다.
- 작업 내용:
  - Gradle task로 `../data/json/*.json` → `app/src/main/assets/data/`에 복사한다(빌드마다 동기화)
  - `assets/maps`, `assets/foods` → `app/src/main/assets/images/`도 같은 방식으로 복사
  - `Seeder.seedIfNeeded()`를 Application 시작 시 코루틴으로 실행
- 완료 기준: 디버그 화면 또는 로그에서 테이블별 건수가 S1-1 결과와 일치한다.

### S2-6. 공통 UI와 테마

- 목적: 모든 화면이 쓰는 부품을 먼저 만든다.
- 작업 내용:
  - 타이포 스케일: 본문 18sp, 제목 22sp, 보여주기 모드 36·28sp. 설정에서 "큰 글씨" 전환 시 1.3배
  - `ShowCardScreen(title, lines, phone?, copyText?)`: 전체 화면, 밝기 최대, 화면 꺼짐 방지, 터치로 UI 숨김, 가로 모드 대응. 택시 카드·문장 보여주기·메뉴 포인팅이 공유한다
  - `DayChips(selected, onSelect)`: D1~D8 가로 스크롤
  - `PhoneButton(number)`: `ACTION_DIAL`
  - `CopyButton(text)`: 클립보드 복사 후 "복사됨" 스낵바
  - `ExternalAppButtons(addrZh, amapUrl?)`: 고덕지도 설치 여부 확인 후 노출. 패키지명 `com.autonavi.minimap`, DiDi `com.sdu.didi.psnger`
  - 다크 테마 기본 지원
- 완료 기준: 샘플 데이터로 ShowCard가 밝기 최대·가로 모드에서 동작한다.

### S2-7. 네비게이션

- 목적: 하단 탭 5개와 상세 화면 경로를 만든다.
- 작업 내용: 경로 문자열을 다음과 같이 정한다.

```
home, schedule?day=, phrases?cat=, maps?day=, more
lodging/{id}, meal/{id}, food/{id}, taxi/{type}/{id}, show/{phraseId}
transport, expense, packing, notes, emergency, settings
```

### S2-8. 커밋

## S3. MVP 화면

### S3-1. 일차 판별과 현재 일정 로직 (`domain`)

- 목적: 오늘 날짜·시각으로 D1~D8과 현재 일정 행을 정한다.
- 작업 내용:
  - `DayResolver.resolve(now)`: 12/16 이전 → `BeforeTrip(daysLeft)`, 12/16~12/23 → `OnTrip(dayId)`, 이후 → `AfterTrip`
  - `CurrentScheduleFinder.find(dayId, now)`: `timeStart <= now < timeEnd`인 행, 없으면 다음 행. 시간대는 Asia/Shanghai로 고정한다(한국 시간과 1시간 차이)
  - `NextMoveFinder`: 이동수단이 열차·투어 차량·빵차·픽업인 다음 행과 남은 분
  - 설정에 "날짜 강제 지정"을 두어 여행 전 테스트가 가능하게 한다
- 완료 기준: 단위 테스트 6건 이상 통과(출발 전·D1 밤·D3 새벽 픽업·D5 트레킹 중·D8 저녁·귀국 후).

### S3-2. 홈(오늘) 화면

- 목적: 구성방안 3.1절 구현.
- 작업 내용: 위에서 아래로 오늘 요약 → 지금 일정 카드 → 다음 이동 카운트다운 → 바로가기 4개 → 오늘의 주의. 여행 전에는 D-day와 준비물 진행률을 표시한다.
- 완료 기준: 날짜 강제 지정으로 D1~D8 각각 확인. 바로가기 4개가 해당 화면으로 이동한다.

### S3-3. 일정 타임라인

- 목적: 구성방안 3.2절 구현.
- 작업 내용:
  - 행 카드: 시간, 출발지→경유→도착지, 이동수단 아이콘, 소요시간, 팁
  - 도착지 문자열이 `lodgings`·`meals`의 이름과 일치하면 링크로 만든다(이름 매칭 테이블은 `data/place_links.json`에 수동 정의)
  - `message`가 있는 행은 "매니저에게 보여주기" 버튼 → `show/` 경로
  - 길게 눌러 완료 표시, 지난 행 흐리게
- 완료 기준: D4 17:00 행과 D6 10:30 행에서 장문 메시지가 전체 화면으로 뜬다.

### S3-4. 택시 카드

- 목적: 구성방안 3.3절 구현. 핵심 기능이므로 가장 먼저 실기기에서 검증한다.
- 작업 내용:
  - `taxi/{type}/{id}`: type은 `lodging | meal | station | poi`
  - 역·공항·관광지 데이터는 `data/places.json`에 수동 작성(쿤밍역 昆明站, 리장역 丽江站, 샹그릴라역 香格里拉站, 창수이공항 昆明长水国际机场, 송찬림사 松赞林寺, 취호공원, 원통사, 상호도협 매표소 등)
  - 화면: `请送我们到这个地址` + 병음 / 상호 중국어(36sp) / 주소(28sp) / 전화 / 보조 문구 / 한국어 이름·예약번호(작게)
  - 보조 문구 규칙: 물라뉴 → 고성 진입 불가 안내문, Come Inn → 짐 전달문, 공항 출발 → `我们有三个行李箱`
  - 버튼: 주소 복사, 고덕지도 열기, DiDi 열기, 전화
- 완료 기준: 실기기에서 밝기 최대·화면 유지·가로 모드 확인. 고덕지도 미설치 기기에서는 버튼이 숨는다.

### S3-5. 회화 화면

- 목적: 구성방안 3.4절 구현(음성은 S5에서 내장 mp3로 교체, 이 단계는 Android TTS만).
- 작업 내용:
  - 상단 탭: 상황별 10개 범주 + 단어장 + 즐겨찾기
  - 항목 카드: 중국어(24sp), 병음, 한글 발음, 한국어 뜻, 스피커 버튼, 별 버튼
  - `TtsPlayer`: `TextToSpeech(zh-CN)` 초기화, 엔진 미설치 시 "음성 데이터 설치" 안내로 시스템 설정 열기. 속도 0.7·1.0 전환, 3회 반복 토글
  - 길게 누르기 → `show/{phraseId}` 전체 화면
  - 장문 메시지 항목은 "위챗용 복사" 버튼만 두고 스피커를 숨긴다
  - 홈 상황 추천: 현재 일정 행의 이동수단·도착지 유형에 따라 범주 1개를 홈에 노출
- 완료 기준: 56문장 모두 재생·복사·전체 화면 동작. 즐겨찾기가 재시작 후 유지된다.

### S3-6. 지도 화면

- 목적: 구성방안 3.5절 구현.
- 작업 내용:
  - `data/maps.json`에 7장 이미지·제목·캡션·`dayIds`·`pins`(맛집 지도 번호 1~15 → mealOption id)를 정의
  - 뷰어: 핀치 줌·더블 탭·드래그(`Modifier.graphicsLayer` + `transformable`), 가로 모드
  - 일차 칩 선택 시 해당 일차 지도만 좌우 페이저로 표시, 전체 보기 탭 별도
  - 맛집 지도는 범례 리스트를 이미지 아래에 두고 터치 시 `meal/` 상세로 이동
  - 상세일정의 Amap 링크 목록을 "실제 지도에서 보기"로 하단에 나열
- 완료 기준: 7장 모두 확대 시 끊김 없음. D5 선택 시 호도협 경로도가 먼저 나온다.

### S3-7. MVP 설치와 피드백

- 작업 내용: 디버그 APK를 3인 기기에 설치한다. 비행기 모드에서 모든 MVP 화면을 열어 본다. 글자 크기·버튼 위치 의견을 수집하여 `docs/feedback.md`에 기록한다.
- 완료 기준: 3대 설치, 오프라인 동작 확인, 피드백 10건 이상 기록.

## S5. 음성 파일 생성과 내장

### S5-1. 생성 엔진 결정

- 목적: 문장 56개·단어 52개·음식명 44개의 mp3를 만든다.
- 작업 내용: 다음 중 하나를 택한다. 기본 권장은 1안이다.
  1. edge-tts(무료, `zh-CN-XiaoxiaoNeural`): `pip install edge-tts`
  2. Google Cloud Text-to-Speech(`cmn-CN-Wavenet-A`): 과금, 품질 높음
  3. Azure Speech: 2안과 유사
- 완료 기준: 샘플 3문장을 생성하여 3인이 듣고 승인한다.

### S5-2. 생성 스크립트 (`tools/gen_audio.py`)

- 작업 내용:
  - 입력: `data/json/phrases.json`, `words.json`, `foodNames.json`
  - 출력: `assets/audio/phrases/{id}.mp3`, 속도 1.0 기본. 느린 버전은 앱에서 재생 속도로 처리한다
  - 이미 존재하는 파일은 건너뛴다(텍스트 해시를 파일명 옆 `.sha` 파일로 기록)
  - `copyOnly: true` 항목은 생성하지 않는다
- 실행:

```bash
python3 tools/gen_audio.py --engine edge --voice zh-CN-XiaoxiaoNeural
```

- 완료 기준: 150개 내외의 mp3, 총 용량 20MB 이하.

### S5-3. 앱 내장과 재생 전환

- 작업 내용: Gradle 복사 task에 `assets/audio` 추가. `TtsPlayer`가 mp3 존재 시 `MediaPlayer`(또는 ExoPlayer)로 재생하고, 없으면 Android TTS로 대체한다. 재생 속도 0.7은 `PlaybackParams`로 처리한다.
- 완료 기준: 비행기 모드에서 전체 문장 재생.
